# 频率隐藏保序加密（FH-OPE）实验说明

## 一、什么是频率隐藏保序加密（FH-OPE）

### 1.1 问题背景

在密文数据库中，保序加密（OPE）允许服务器在密文上执行大小比较操作，但存在一个严重的安全问题：**频率攻击**。

例如，如果数据库中"apple"出现了1000次，而"banana"只出现了2次，攻击者可以通过观察密文的分布频率推断哪些密文对应"apple"。

**频率隐藏保序加密（Frequency-Hiding OPE，FH-OPE）** 的核心目标是：
> 相同的明文多次加密得到的密文不同，但密文之间的顺序仍然与明文保持一致。

### 1.2 形式化定义

给定两个密文 $c_1$ 和 $c_2$，如果满足 $\text{ord}(c_1) < \text{ord}(c_2)$，则必然有对应的明文 $m_1 < m_2$。

**举例说明：**

| 明文序列 | 1 | 4 | 4 | 5 | 5 | 7 |
|---------|---|---|---|---|---|---|
| 密文序列 | 13 | 14 | 16 | 17 | 19 | 21 |

注意：两个"4"被加密成了不同的密文（14和16），两个"5"也被加密成了不同的密文（17和19），这隐藏了它们的真实频率。

## 二、FH-OPE 的两种方案

### 2.1 有交互的 FH-OPE（2015年，Kerschbaum）

**方案特点：**
- 客户端维护一棵二叉排序树（ BST）
- 通过参数设定减少排序树的调整
- 缺点：树一旦调整会带来巨大性能消耗；客户端大存储使方案不实用

**工作原理：**
1. 初始化二叉排序树为空
2. 加密明文时，从根节点开始遍历
3. 若当前节点的明文等于插入明文，则生成随机数
4. 否则继续向下层遍历

### 2.2 无交互的 FH-OPE（2021年，Li等人）

**方案特点：**
- 小客户端存储，无需额外交互
- 提出了**编码树**的概念（改进B+树）
- 中间节点存储后代中包含的密文数量，而非关键词
- 可在1次交互下将密文插入B+树

**编码树结构：**
- 每个叶节点存储多个密文及其对应的编码
- 每个中间节点存储其子节点的密文个数
- 通过区域编码策略，支持高效的插入和查询

## 三、FH-OPE 编码树实现

### 3.1 节点类型

```cpp
class Node           // 基类
class InternalNode   // 内部节点：存储子节点指针和每个子节点的密文数量
class LeafNode        // 叶节点：存储密文和对应的编码
```

### 3.2 编码策略

**叶节点编码：**
- 每个叶节点有一个编码区间 `[lower, upper)`
- 插入新密文时，在区间内选择合适位置编码
- 若区间不足，则触发重编码（Recode）

**区域编码更新策略：**
- 当树需要平衡调整时，**不更新**密文的保序编码
- 采用区域编码策略，插入只可能引发节点内数据密文编码更新，其他节点不发生更新

### 3.3 插入操作流程

```
1. 客户端使用 local_table 记录每个明文出现的次数
2. 计算待插入明文的位置 pos（考虑之前的出现次数）
3. 服务器在编码树中找到对应的叶节点
4. 在叶节点的区间内分配编码
5. 若叶节点满，则分裂（rebalance）
```

### 3.4 关键算法

**CalPos 函数：** 计算明文在全局顺序中的位置
```python
def CalPos(plaintext):
    # 统计有多少密文小于等于该明文
    presum = sum([v for k, v in local_table.items() if k < plaintext])
    if plaintext in local_table:
        # 返回一个随机位置（该明文出现的位置范围内）
        return random.randint(presum, presum + local_table[plaintext] - 1)
    else:
        return presum
```

## 六、核心概念速查

| 概念 | 说明 |
|------|------|
| FH-OPE | Frequency-Hiding Order-Preserving Encryption，频率隐藏保序加密 |
| 编码树 | 改进的B+树，中间节点存储密文数量而非关键词 |
| 区域编码 | 避免树平衡调整时更新所有密文编码的策略 |
| UDF | User-Defined Function，用户自定义函数，MySQL扩展接口 |
| local_table | 客户端维护的明文-计数表 |
